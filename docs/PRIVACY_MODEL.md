# Privacy Model

TrustGate is local-first by design. No data leaves your machine unless you explicitly configure a hybrid or cloud mode.

## Operating Modes

### Local (default)

All processing runs on-device. TrustGate makes zero network calls in local mode -- no DNS lookups, no telemetry endpoints, no update checks. Scan results, SARIF files, and remediation guidance stay on the local filesystem under your control.

### Hybrid

Redacted summaries are sent to a configured remote endpoint for aggregation (e.g., organisational dashboards). The following fields are stripped before transmission:

| Redacted field | Replacement |
|---|---|
| Source code snippets | `[REDACTED]` |
| Absolute file paths | Relative project paths only |
| Developer / committer names | Anonymous hash |
| Repository URLs | Organisation-scoped identifier |
| Environment variables in findings | `[REDACTED]` |

What is transmitted:

- Severity counts (critical / high / medium / low)
- Scanner metadata (tool name, version, rule IDs)
- CWE and CVE identifiers
- Timestamps

### Cloud

Full findings -- including source snippets and file paths -- are transmitted to the configured remote. This mode requires explicit opt-in via `trustgate config set mode cloud` and an interactive confirmation prompt. Cloud mode is intended for teams that run TrustGate in a controlled CI environment with an internal backend.

## Telemetry

TrustGate ships with telemetry **disabled**. Opting in (`trustgate config set telemetry on`) sends only:

- CLI command names (no arguments or file paths)
- Execution duration
- Python and TrustGate version
- OS type (no hostname)

Telemetry never includes scan results, source code, or personally identifiable information. Opt out at any time with `trustgate config set telemetry off`.

## Data Retention and Deletion

- **Local artefacts** (SARIF reports, evidence bundles, benchmark results) persist until you delete them. Run `trustgate clean` to remove all generated output.
- **Hybrid / Cloud backends** follow the retention policy of the receiving service. TrustGate itself does not enforce remote retention periods.
- **Telemetry data**, when opted in, is retained for 90 days and then purged automatically.

## Compliance Considerations

### GDPR

- No personal data is processed in local mode.
- Hybrid mode anonymises developer identities with irreversible hashes before transmission, satisfying data-minimisation requirements.
- Users can exercise the right to erasure by running `trustgate clean` locally and requesting deletion from any configured remote backend.

### SOC 2

- Local-first architecture supports the confidentiality and privacy trust-service criteria by default.
- Audit evidence generated by `trustgate evidence` includes tamper-evident checksums, supporting integrity controls.
- Telemetry opt-in with explicit consent aligns with the notice-and-choice privacy principle.

## Summary

| Concern | Local | Hybrid | Cloud |
|---|---|---|---|
| Network calls | None | Redacted summaries | Full findings |
| Source code leaves machine | No | No | Yes (opt-in) |
| File paths transmitted | No | Relative only | Yes |
| Developer names transmitted | No | No (hashed) | Yes |
| Telemetry | Off by default | Off by default | Off by default |
